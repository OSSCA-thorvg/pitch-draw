# 06 — 계기판

**Spec:** `.scratch/core-play-loop/spec.md`

**What to build:** 연주 중 안쪽 숫자가 조금 드러난다. 지금 내가 내는 음의 이름과 주파수, **지금 내야 할 목표 음**, 목표 대비 오차, 진행도, 음정 신뢰도, 악보의 점 개수와 발견된 도형 개수, 입력 신호 세기.

연주자에게는 실용이다 — 현재 음과 목표 음이 나란히 보이면 올려야 할지 내려야 할지 알 수 있고, 신호 세기가 보이면 소리가 마이크에 들어가고는 있는지부터 확인할 수 있다.

심사위원에게는 다른 값어치가 있다. PLAN.md 2절 마항 "깊이의 암시" — 실제 난이도와 무관하게 **안을 아는 사람이 만들었다는 인상**을 준다. 비용 대비 효과가 크다.

오차는 픽셀이 아니라 **센트** 단위로 보여준다. 화면 좌표 차이로 표시하면 음역 상수를 바꿀 때 의미가 흔들린다.

**이 티켓은 일부러 떼어놨다.** 시간이 모자라면 여기부터 잘라낸다. PLAN.md 2절의 인상 장치 중 즉시성(나)은 마지막까지 지키고, 깊이의 암시(마)를 먼저 깎는다.

**Blocked by:** 03 — 목표 음과 오차는 연주가 돌아가야 나온다.

**Status:** ready-for-human — 구현은 끝났다. 남은 것은 마이크와 눈이 필요한 확인뿐이다 (아래 Comments 참고).

- [ ] 목표 대비 오차가 센트 단위로 보이고, 올려야 하는지 내려야 하는지 알 수 있다
- [x] 진행도가 보인다

## Comments

**구현 완료.** 스테이지 아래 계기판에 일곱 가지를 띄운다 —
지금 내는 음(이름+Hz), 내야 할 음(이름+Hz), 오차(센트), 진행도, 음정 신뢰도,
악보의 점 개수와 도형 개수, 입력 신호 세기.

숫자는 매 프레임이 아니라 100ms 마다 옮기고, 값에는 지수 스무딩을 걸었다.
읽으라고 있는 것이지 판정에 쓰는 값이 아니다. 소리가 잡히지 않으면 음·오차·신뢰도를
`—` 로 비운다 — 마지막 값이 남아 있으면 그게 지금 값인 줄 안다.
신호 세기 막대만은 매 프레임 갱신한다. "소리가 마이크에 들어가고는 있는가"는
음정이 안 잡히는 동안에도 알아야 하는 것이라, 오디오 입력 모듈이 표본과 별개로
마지막 RMS 를 들고 있게 했다.

오차는 픽셀이 아니라 센트다. 25센트를 넘으면 올려라/내려라를 말해준다.

**검증** — 헤드리스에서 확인했다. 준비 상태에서 원 예제의 `내야 할 음`이
**C#4 / 284.4 Hz** 로 뜬다. 원의 시작점(3시 방향)은 세로 한가운데라 음역의 기하평균
`sqrt(130 × 622) = 284.4 Hz` 가 나와야 맞다. 악보 칸도 `점 400 · 도형 1` 로 뜬다.
소리가 없을 때 현재 음이 `—` 로 남는 것도 확인했다.

**남은 확인(사람 필요)** — 마이크가 있어야 하는 것들이다.
- 현재 음·주파수·신뢰도·신호 세기가 실제 소리에 맞게 뜨는지
- 오차 센트와 올려라/내려라 방향이 맞는지
- 숫자가 읽을 수 있는 속도로 갱신되는지 (100ms 로 잡았지만 눈으로 봐야 안다)
