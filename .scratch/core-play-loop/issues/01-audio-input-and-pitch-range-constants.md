# 01 — 프리팩터: 오디오 입력 분리 · 음역 상수 통일

**Spec:** `.scratch/core-play-loop/spec.md`

**What to build:** 앱의 겉보기 동작은 이 티켓 전후로 **완전히 같다**. 시작을 누르면 마이크 권한을 묻고, 소리를 내면 점이 위아래로 움직이고 지나간 자리에 선이 남는다. 장치 선택과 새로고침도 그대로다.

바뀌는 건 안쪽 둘이다.

1. **오디오 입력이 진입점에서 떨어져 나온다.** 장치 목록·`getUserMedia`·분석기 배선이 한 모듈이 되고, 프레임마다 `{hz, clarity, rms}` 또는 `null`을 내놓는다. 이후 티켓들이 마이크 배선을 다시 건드리지 않게 하기 위해서다.
2. **음정과 세로 위치를 오가는 매핑 상수가 한 곳으로 모인다.** 지금 음 높이 추출 쪽의 표시용 변환과 확인용 프로토타입의 악보 음역이 서로 다른 범위를 쓰고 있다. 이대로 두면 악보가 정한 목표 음을 정확히 불러도 펜이 목표선 위에 오지 않는다. **"정확히 부르면 목표선과 겹친다"는 이 게임의 유일한 성공 신호이고, 그게 성립하려면 두 변환이 같은 상수를 쓰는 정확한 역함수여야 한다.**

음 높이 추출 알고리즘 자체(자기상관, RMS 게이트, 신뢰도 임계값)는 손대지 않는다. 이미 동작이 확인된 부분이다.

**Blocked by:** 없음 — 바로 시작할 수 있다.

**Status:** ready-for-human — 구현은 끝났다. 남은 것은 마이크와 눈이 필요한 확인뿐이다 (아래 Comments 참고).

- [ ] 시작 → 권한 요청 → 소리에 반응해 선이 그려지는 기존 동작이 그대로 재현된다
- [ ] 장치 선택과 장치 새로고침이 그대로 동작하고, 권한 승인 후 장치 이름이 채워진다
- [x] 오디오 입력 모듈이 프레임당 `{hz, clarity, rms} | null`을 내놓고, 그 밖의 것(그리기·화면 상태)을 알지 못한다
- [x] 신호 가공(echoCancellation·noiseSuppression·autoGainControl)이 여전히 전부 꺼져 있다
- [x] 입력이 출력에 연결되지 않는다 (하울링 방지)
- [x] 음정 → 세로 위치, 세로 위치 → 음정 변환이 하나의 음역 상수를 공유하며, 서로 정확한 역함수다
- [x] 임의의 주파수를 넣어 두 변환을 왕복시키면 원래 값으로 돌아온다 (경계 밖은 클램프)
- [x] 음역 상수가 한 곳에만 존재한다 — 같은 의미의 숫자가 두 군데 남아 있지 않다

## Comments

**구현 완료.** `src/audio-input.js` 가 장치 목록·`getUserMedia`·분석기 배선을 가져갔고,
음역 상수는 `src/range.js` 한 곳으로 모였다. `pitch.js` 에 있던 표시용 `hzToUnit`(100~800Hz)은
삭제했다 — 프로토타입의 악보 음역(130~622Hz)과 다른 값을 쓰고 있어서, 그대로 두면
목표 음을 정확히 불러도 펜이 목표선에 오지 않았다.

`pitch.js` 의 `MIN_HZ`/`MAX_HZ`(70~1200)는 남겼다. "음정을 잡아볼 범위"라서
"부를 수 있는 음역"과 뜻이 다르다. 헷갈리지 않게 주석으로 갈라뒀다.

**검증** — 왕복 변환을 수치로 확인했다(스크래치 스크립트, 저장소에는 남기지 않음).
음역 안 1001개 지점에서 `hz→unit→hz`, `y→hz→y`, `hz→y→hz` 모두 상대오차 1e-12 미만.
경계 밖은 `LOW_HZ`/`HIGH_HZ` 로 클램프된다. 한 옥타브 = 1200센트도 확인.

**남은 확인(사람 필요)** — 마이크가 있어야 하는 것들이다.

- 첫 항목("겉보기 동작이 그대로 재현된다")은 **이제 해당하지 않는다.** 03에서 스윕 방식이
  통째로 대체되어 사라졌다. 01만 따로 떼어 확인할 수 있는 시점은 지났다.
